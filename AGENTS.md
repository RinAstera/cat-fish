# Правила для ИИ-исполнителя

## Цель и границы работы

Создать мини-игру с видом сверху: оригинальный котик гуляет, подбегает к выбранной рыбке, съедает её и увеличивает счётчик. Выполнять задачи из `TASKS.md` по порядку, по одной за заход. Не реализовывать следующие задачи заранее. Перед работой прочитать оба файла и текущий код; после работы проверить критерии текущей задачи и отметить её `[x]` только при их выполнении. В отчёте перечислить изменения и реально проведённые проверки. Если браузер недоступен, явно сообщить об этом и не выдавать ручную проверку за выполненную.

## Стек и структура

- Только HTML5, CSS и чистый JavaScript; графика — Canvas 2D, интерфейс счётчика — HTML.
- Без фреймворков, библиотек, пакетного менеджера, сборщика и обязательного сервера.
- `index.html` — русскоязычная страница, canvas, счётчик и краткая инструкция.
- `styles.css` — полноэкранная компоновка, фон, счётчик, адаптивность и сенсорное поведение.
- `js/drawing.js` — рисование котика и рыбки примитивами Canvas; не изменяет состояние игры.
- `js/game.js` — состояние, движение, появление рыбок, выбор цели и поедание.
- `js/main.js` — получение DOM-элементов, настройка canvas, события указателя и размера окна, единственный цикл анимации.
- `AGENTS.md` и `TASKS.md` — инструкции и план; дополнительных файлов без необходимости не создавать.

JS-файлы подключать обычными относительными `script src` с `defer` в порядке `drawing.js`, `game.js`, `main.js`. Не использовать модули, `import`, `fetch` или загрузку ресурсов, требующую HTTP: обязательна работа через `file://`. Все пути относительные, без начального `/`, чтобы публикация в подпапке GitHub Pages не требовала изменений.

## Соглашения по коду

- Отступы — 2 пробела; точки с запятой; `const` по умолчанию, `let` только для изменяемых значений; без `var`.
- Имена переменных и функций — понятные английские `camelCase`, констант — `UPPER_SNAKE_CASE`. Тексты интерфейса и поясняющие комментарии — на русском.
- Небольшие функции с одной ответственностью. Без сложной иерархии классов и преждевременных абстракций.
- Единственное общее пространство имён — `window.CatFish`; внутренние переменные файлов изолировать. Настройки скорости, размеров и времени хранить в именованных константах в соответствующем файле.
- Согласованный минимальный интерфейс: `drawing.drawCat` и `drawing.drawFish` рисуют объекты; `game.createState`, `game.update`, `game.selectFish`, `game.resize` управляют состоянием. Точные аргументы определить при введении функции и кратко пояснить рядом. `main.js` связывает эти части, но не содержит правила движения и поедания.
- Один `requestAnimationFrame`; время движения и анимаций считать по `deltaTime` в секундах, ограниченному сверху 0,05 с. Не создавать отдельные циклы или интервалы для отдельных объектов.
- Координаты игры и скорости считать в CSS-пикселях. Физическое разрешение canvas масштабировать по `devicePixelRatio`, не меняя систему координат игры.
- Не добавлять зависимости ради форматирования, тестов или запуска. После каждой задачи достаточно целевой ручной проверки и проверки консоли браузера.

## Правила игры и спорные случаи

- Котик оригинальный, нарисованный геометрическими примитивами, узнаваемый сверху: тело, голова, уши, лапки и хвост. Не копировать известных персонажей. Движение лап и хвоста зависит от времени; при ходьбе кот ориентирован по направлению движения.
- Состояния кота: `wandering` (неспешная прогулка с паузами), `chasing` (бег к цели), `eating` (короткое поедание на месте). Бег заметно быстрее прогулки.
- Рыбка появляется через случайные 2–4 секунды в безопасном месте поля; максимум 5 одновременно, включая поедаемую. При заполнении лимита пропускать появление, без накопления очереди. Рыбки сами не исчезают.
- Не размещать рыбок под счётчиком, за границей поля, внутри кота или поверх других рыбок. Ограничить подбор позиции 30 попытками; если места нет — пропустить появление. Не использовать бесконечный поиск свободного места.
- Каждая рыбка имеет уникальный ID. Во время погони новое нажатие переключает цель; нажатие на пустое место ничего не меняет. Во время поедания нажатия игнорируются. Очереди целей нет.
- По достижении цели кот останавливается примерно на 0,5 с, выполняет видимую анимацию поедания, затем рыбка удаляется и счётчик увеличивается ровно на 1. До конца анимации рыбка остаётся в списке. После еды кот возвращается к прогулке.
- Счётчик начинается с 0 при загрузке страницы; сохранение между загрузками не требуется.
- Использовать единый `pointerdown` для мыши и касаний, без дублирующих обработчиков `click`/`touchstart`. Координаты переводить через `getBoundingClientRect`. Область нажатия на рыбку — не меньше 44 × 44 CSS-пикселей; если области пересеклись, выбирать ближайшую рыбку к точке нажатия.
- При изменении размеров сохранять счётчик и состояние игры, переносить объекты и цели в допустимые границы. Позицию цели погони брать по ID рыбки, а не из устаревшей копии координат. Не допускать отрицательных диапазонов случайных координат на маленьком поле.
- Рабочий ориентир — экран от 320 × 320 CSS-пикселей, обе ориентации. На ещё меньшем поле допускается пропуск появления рыбок, но не ошибки и зависания.

## Запуск и проверка

1. Открыть `index.html` двойным кликом в современном браузере: адрес должен начинаться с `file://`, установка и команды не нужны.
2. Открыть инструменты разработчика и проверить отсутствие ошибок в консоли и неудачных загрузок ресурсов.
3. Выполнить ручные шаги текущей задачи из `TASKS.md`; после изменения общей логики повторить соответствующие проверки предыдущих задач.
4. Для адаптивности использовать режим устройств браузера, размеры 320 × 568 и 568 × 320, а также обычное окно ПК и изменение его размера. Для итоговой проверки тапа по возможности использовать реальный телефон; эмуляцию не называть проверкой на телефоне.
5. Для публикации достаточно разместить `index.html`, `styles.css` и папку `js` на статическом хостинге. Деплой не входит в эти задачи.

## Запреты

- Не менять файлы вне текущей задачи и не удалять чужие изменения. При необходимой зависимости от другого файла кратко обосновать изменение до его внесения; не делать попутный рефакторинг.
- Не добавлять библиотеки, фреймворки, сборщики, зависимости, внешние картинки, шрифты, CDN и сетевые запросы.
- Не добавлять сервер, обязательный локальный HTTP-запуск, аналитику, аккаунты, звук, сохранения, уровни и другие незаказанные функции.
- Не менять этот план и правила ради обхода критериев готовности; разрешено отмечать завершённые задачи в `TASKS.md`.
- Не публиковать сайт и не выполнять Git-операции с удалённым репозиторием без отдельного поручения.
